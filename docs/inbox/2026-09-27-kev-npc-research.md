# Kev для решений NPC: проверка и план

**Предложение исследователя, не принятое решение.** Разбор [идеи](2026-09-27-kev-npc-idea.md), 27.09.2026.

## 1. Что такое Kev

Модель существует и в целом совпадает с описанием.

| Что | Факт | Источник |
|---|---|---|
| Автор, код | Jared Palmer, [github.com/jaredpalmer/kev](https://github.com/jaredpalmer/kev). Открытая реконструкция закрытой Jev (TypeSafe) | README |
| Лицензия | Apache-2.0, базы Qwen тоже Apache-2.0 | README |
| Дата | Репозиторий с 17.09.2026, текущая Kev-0.8B — 24.09.2026. Статус Alpha, проекту 10 дней | [карточка 0.8B](https://github.com/jaredpalmer/kev/blob/main/docs/model-cards/kev-0.8b.md) |
| Размеры | 0.8B, 4B, 9B (Qwen3.5-Base), 27B (Qwen3.8). Каждая — LoRA r16 и pointer head | README |
| Запрос | `POST /v1/systemone`: `state` (строка или JSON, превращается в размеченный текст) и `questions` трёх типов: `noul` (да/нет), `choice` (1–255 вариантов с описаниями), `score` (упорядоченные уровни). Ответ — калиброванные вероятности, текст не генерируется. Вопросы не видят друг друга | README, раздел API |
| Запуск | Python 3.12–3.13 и uv: `python -m kev.serve --run jaredpalmer/kev-0.8b --port 8008`. FastAPI на 127.0.0.1, протокол HTTP/JSON. CUDA, ROCm, MLX | README |
| Дообучение | JSONL «как запрос + `label`», `kev.train --init_from jaredpalmer/kev-0.8b`. «`--batch 1 --accum 8` in bf16 fits the 0.8B model on a 4 GB GPU» | README |

**Цифры из исходника.**
- L4, Kev-0.8B, 6 вопросов: 22,7 мс на новый state и 16,1 мс на закешированный, 62,8 запроса/с при 64 клиентах. Это время модели без сети. **Подтверждено** ([Serving Performance](https://github.com/jaredpalmer/kev#serving-performance)). State в 2200 токенов: 108,6 мс. «Около 109» — верно.
- Out-of-domain 0,65: **подтверждено**. Development 0,648, locked test 0,697, у прошлой версии 0,652. In-domain — 0,827.
- Обучение в 4 ГБ: **заявление автора**, нами не проверено.
- Батчинг, CUDA graphs, fused kernels: **подтверждено кодом**. Модельный поток забирает до 64 ждущих запросов в один батч (`kev/serve.py`, `kev/cuda_graphs.py`, `kev/fused_qwen35.py`). Отдельного batch-эндпоинта нет: батч складывается из одновременных HTTP-запросов.
- «Kev-server» как отдельный продукт в официальном репозитории не найден. Сервер — это `kev.serve`. Пакет `@kev-ai/server` упоминается рядом со сторонним проектом, не с этим.

**Не подтверждено.**
- **Windows.** Официально не заявлена. Python-часть на Windows запускали ([issue #12](https://github.com/jaredpalmer/kev/issues/12)). Быстрый путь для Qwen3.5 требует `flash-linear-attention`, то есть Triton, а у официального Triton нет сборок под Windows. Надёжнее всего WSL2.
- **Blackwell sm_120.** В документации нет. Косвенно: `torch>=2.6,<2.9` допускает сборки cu128 с поддержкой sm_120, а автор сравнивал на RTX PRO 6000 Blackwell под Linux ([#107](https://github.com/jaredpalmer/kev/issues/107)).
- **5070 Ti.** Замеров нет. Память 0.8B не указана: веса bf16 занимают около 1,6 ГБ, плюс буферы графов. «До 4 ГБ» правдоподобно, но нужно замерить.
- **Альтернатива без Python.** [ggmlc](https://github.com/monatis/ggmlc/blob/main/examples/laya/README.md) — GGUF и один exe с тем же API. Сборки есть только под sm80–89, 0.8B на RTX 4050 отвечает за 465 мс. Сыро.

**Существенные ограничения 0.8B** из карточки:
- правила собирает плохо: «(A and B) or not C» — 0,56, «if A then not B else C» — 0,59;
- обучена на state до 384 токенов;
- на ответ влияет порядок вариантов;
- автор советует 4B, если важна точность.

## 2. Применения в нашем мире

Kev полезен там, где много мягких факторов, нужна вариативность и надо выбирать по смыслу из описанного текстом контента. Жёсткие правила и реакции лучше оставить behavior tree или utility AI.

| Применение | Вопросы | Оценка |
|---|---|---|
| **Поселенцы базы:** чем заняться | `intent` choice: build, gather, rest, cook, talk_to_hero, tend_plants, explore; `helps` choice — кому помочь; `mood` score | **Лучше utility AI.** Потребности, характер, отношения, погода и состояние базы без сотен коэффициентов, а сэмплирование даёт живость |
| **Реплика компаньона или призрака** из заранее написанного пула | `line` choice: до 255 реплик с описаниями, `speak_now` noul | **Сильнейший случай.** Pointer head подбирает реплику к контексту: руина светится, герой устал, рядом портал. В дереве для этого нужна ручная разметка тегами |
| **Фрагмент памяти призрака прошлого:** что открыть герою | `memory` choice по фрагментам лора, `ready` noul — готов ли герой | Хорошо. Прогресс героя и найденные предметы учитываются без явной таблицы условий |
| **Торговец:** настроение сделки | `offer` choice: discount, fair, gift, refuse; `trust` score | Средне: формула справится, Kev добавляет характер |
| Животные, растения, вакуумный конь | — | **Избыточен.** Реакции простые и срочные, конь — сюжетный |

Пример state для поселенца. Писать по-английски: модель учили на английском.

```yaml
self: {role: settler, name: Ora, traits: [curious, lazy, kind], energy: .35, hunger: .6}
hero: {near: true, relation: .8, carrying: sandstone, last_talk_min: 40}
base: {food: low, unfinished: [wall_east], plants_glowing: 3}
world: {time: evening, weather: warm_rain}
events: [hero_returned, storage_full]
```

Вопросы:

```yaml
intent: {type: choice, criteria: {cook: "...", build: "...", rest: "...", talk_to_hero: "..."}}
mood:   {type: score, criteria: [gloomy, calm, cheerful]}
```

## 3. Интеграция с Godot

```
NPC ──request(state, questions)──▶ Decisions (autoload: очередь)
                                   │ до N=8 запросов одновременно
                                   ▼
                         Decider (интерфейс)
             ├─ KevDecider: HTTPRequest ⇄ kev.serve, localhost
             ├─ SyntheticDecider: спеки, заданные ответы
             └─ FallbackDecider: правила, если сервера нет
```

- **Процесс.** В разработке сервер поднимается вручную или скриптом в WSL2. Игра при старте проверяет `GET /v1/models`. Позже игра запускает его сама через `OS.create_process` и гасит на выходе.
- **Без блокировки.** `HTTPRequest` асинхронный, `Decider.decide()` — корутина: NPC вызывает её через `await`, а до ответа выполняет прежнее намерение. Батч складывает сервер. Нам нужен только пул из N одновременных запросов, свой протокол батча не нужен.
- **Очередь.** Храним один последний запрос на NPC: новый вытесняет устаревший. Ответ на устаревший запрос отбрасываем по номеру. События идут вперёд плановых. Таймаут 300–500 мс, после него решает FallbackDecider.
- **Частоты.** Для тёплого мира хватит планового решения раз в 5–15 с на NPC рядом и раз в 30–60 с вдали. На событие вроде «герой заговорил» или «склад полон» решаем сразу, но не чаще раза в 1–2 с на NPC. Общий лимит — 20 запросов/с.
- **Сэмплирование** через `RandomNumberGenerator` с сидом. Если `confidence` ниже порога, берём вариант из правил.
- **Спеки.** Ответ SyntheticDecider задаётся на сценарий: `{question_id: probabilities}`. Неожиданный набор вопросов — ошибка проверки, как требуют testing-rules. Спека проверяет, что NPC исполняет полученное решение и не ждёт ответа. Качество модели спеками не проверяется.
- **Сервер не запущен.** Всё работает на FallbackDecider. Раз в 30 с проверяем здоровье сервера, в журнал пишем одно сообщение, в игре ошибок нет.

## 4. План экспериментов

| Шаг | Что делаем | Критерий успеха | Трудоёмкость | Риски |
|---|---|---|---|---|
| **0. Замер** | Kev-0.8B и Kev-4B в WSL2; затем попытка native Windows. Нагрузка — `scripts/serving_bench.py` из репозитория или свой клиент: 5 вопросов, state 150–300 токенов, 1/8/32/64 клиента. Второй прогон — одновременно с `levels/world.tscn` | 0.8B: p50 модели ≤ 30 мс, запрос с дороги ≤ 50 мс, ≥ 50 запросов/с, VRAM ≤ 4 ГБ. При нагрузке 20 запросов/с p99 кадра растёт не больше чем на 1 мс | 0,5–1 день | Сборки Triton и fla под Windows. Модель и игра делят GPU: вычисления Kev могут давать рывки кадра — главный риск шага |
| **0б. Качество «из коробки»** | 30 ситуаций поселенца с ожидаемым ответом от Сергея; сравнить 0.8B и 4B | На явных случаях ≥ 80% совпадений, на спорных распределения выглядят разумно | 0,5 дня | 0.8B плохо собирает правила: может понадобиться 4B или LoRA |
| **1. Один NPC** | Минимальный поселенец: капсула и `NavigationAgent3D`, 3 намерения. Decider, KevDecider, SyntheticDecider, FallbackDecider, очередь. Одна спека на синтетике | Кадр не ждёт. Решения видны и различаются по характеру. При выключенном сервере всё работает без ошибок. Спека проходит без сети | 3–4 дня: NPC в игре ещё нет, основное время уйдёт на его тело и навигацию | Раздувание: не строить общую систему ИИ раньше второго NPC |
| **2. Датасет** | Генератор state из случайных факторов. Явные случаи размечает правило, спорные — большая LLM, со сверкой Сергеем выборки | 2–5 тыс. записей, отложено 15%. В README 400 записей давали прирост в пределах шума, 1050 — давали | 2–3 дня | Если метки только от правил, Kev лишь повторит правила. Ценность в разметке спорных случаев |
| **3. LoRA** | `kev.train --init_from jaredpalmer/kev-0.8b --lr 2e-5` на 5070 Ti, `kev.benchmark` на отложенных данных | +10 п.п. на нашем наборе, общий out-of-domain не падает больше чем на 2 п.п. | 1 день, обучение < 1 ч | Переобучение на шаблонах: 0.8B плохо переносит перефразирование |

## 5. Вопросы к Сергею

1. Когда нужны NPC и какие? В фичах их пока нет. Kev ли нужен раньше самих NPC?
2. Kev только для твоей машины или для игроков? Для релиза Python, веса и NVIDIA — тяжёлая зависимость. Нужен будет путь через GGUF или ONNX и запасной режим без GPU.
3. Подходит ли WSL2 для разработки?
4. Сколько VRAM можно отдать Kev рядом с рельефом и объёмным туманом: 2, 4 или 8 ГБ (8 — это уже 4B)?
5. Нужна ли воспроизводимость решений при сохранении и загрузке? Если да, сид и история сэмплирования войдут в сохранение.
6. Можно ли размечать датасет платной LLM, например Claude API? Какой бюджет?
7. Какие реплики и фрагменты памяти будут писаться вручную? Размер пула определяет пользу применения «реплика по контексту».
